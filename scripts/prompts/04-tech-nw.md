## 読者像（最重要）

**IT の知識がゼロの人**です。学生・事務職・営業職。「サーバ」「プロトコル」を一度も使ったことがない人が読みます。

- 専門用語は初出のその場で必ず言い換える。「後で説明します」は禁止
- **この章は郵便・電話・住所にたとえると全部つながります。** IP アドレスは住所、ドメイン名は住所に付けた覚えやすい名前、DNS は電話帳、パケットは荷物を小分けにした宅配便、プロトコルは「どういう手順でやり取りするかの約束」
- 1 文を短く
- カタカナ語・アルファベットの略語には、元の英語とその意味を添える（例：DNS＝Domain Name System、名前と住所の対応表）

読者は普段 Wi-Fi も URL もメールも使っています。**「あなたが毎日やっているこの操作の裏側で、こう動いている」という順序で書いてください。**

## 書き方の注意

- 本文は TypeScript のテンプレートリテラル内に入ります。バックスラッシュは 2 つ重ね、バックティックはエスケープが必要です
- **bash のヒアドキュメントはバックスラッシュを落とすので使わないこと。** ファイルを直接書くか、`scripts/emit_textbook.py`（Markdown を Python の raw 文字列で書いて .ts に変換する小道具）を使ってください
- 図（三連バッククォート + `diagram:flow` / `stack` / `compare` / `tree` / `cycle` / `seq`）を積極的に使ってください。**階層の考え方は `stack`、ブラウザとサーバのやり取りは `seq` が向いています**
- `compare` は「1 行 1 セル、偶数行が左・奇数行が右」で書きます。**要素が奇数個だと検査でエラーになります**
- 図の中では `**強調**` が効きません。書かないでください
- 節からのリンクは `[文字](textbook/t-nw-2)` の形。**存在するのは `i-1`〜`i-4`、`s-corp-1`〜`s-corp-5`、`m-dev-1`〜`m-dev-3`、`m-pm-1`〜`m-pm-2`、`m-sm-1`〜`m-sm-3`、`t-basic-1`〜`t-basic-4`、`t-algo-1`〜`t-algo-3`、そして今回書く `t-nw-1`〜`t-nw-4` だけ**です。それ以外へはリンクしないこと（`t-sec-*` は別の人が同時に書いているので、リンクしないでください）

## 事実の扱い

**確信のない事実は書かないでください。** 特に間違えやすい箇所：

- ルータは異なるネットワークどうしをつなぐ機器、スイッチ（スイッチングハブ）は同じネットワーク内で通信先を選んで転送する機器
- TCP は確実に届けることを重視、UDP は速さを重視（欠けても再送しない）
- POP はメールを手元に取り込む方式、IMAP はサーバに置いたまま見る方式
- HTTPS は HTTP の通信を暗号化したもの
- プライベート IP アドレスはそのままではインターネットに出られず、NAT でグローバル IP に変換される
- 伝送時間の計算では、単位（ビットとバイト、K/M/G）の取り違えに注意して例を示すこと
