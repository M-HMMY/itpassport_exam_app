# 教本の通しレビュー（ひな形）

書いた本人には自分の間違いが見えません。このプロンプトは、**書いた担当とは別の目**で教本を読み直させるためのものです。`{{FILES}}` を担当ファイルに差し替えて使います。

```bash
codex exec --cd "C:\Dev\itpassport_exam_app" --sandbox read-only --color never \
  -o review-1.txt - < review-1.md
```

- `--sandbox read-only` … **レビューは書き換えない。** 指摘だけさせて、直すのは依頼した側
- 1 ジョブ 1〜2 ファイル。ファイルをまたぐ矛盾も見てほしいので、章のまとまりで割る

---

以下がプロンプト本体です。

---

あなたは ITパスポート試験の学習アプリの教本を**検証する**担当です。書いたのは別の担当者です。あなたの仕事は、書き直すことではなく、**間違いを見つけて報告すること**です。

## まず読むもの

- `CLAUDE.md` … このアプリの方針。特に「読者は IT の知識がゼロの人」という前提
- **担当ファイル: {{FILES}}**

## 絶対にしないこと

- **ファイルを 1 文字も書き換えないでください。** サンドボックスは読み取り専用です
- `npm run check` などのコマンドを実行しないでください（他のジョブと同時に走っています）

## 何を見るか

優先順です。上ほど重大です。

### 1. 事実の誤り

ITパスポートの出題範囲として**間違っている記述**を探してください。あなたの知識と照らして、少しでも怪しいと思ったら挙げてください。「たぶん合っている」で流さないでください。

**特に間違いが多い箇所を名指しします。ここは 1 つずつ確かめてください。**

- **法律の年数** … 著作権の保護期間（著作者の死後何年か、法人著作は公表後何年か）、特許権・実用新案権・意匠権・商標権のそれぞれの存続期間と起算日。**過去に改正があった項目なので、古い年数が書かれていないか特に注意**
- **公開鍵暗号の鍵の使い分け** … 暗号化は受信者の公開鍵、復号は受信者の秘密鍵。デジタル署名は送信者の秘密鍵で作り、送信者の公開鍵で検証
- **単位と桁** … ビットとバイト、K/M/G/T の換算、2 進数と 10 進数の変換結果
- **計算結果** … 稼働率（直列は積、並列は $1-(1-a)(1-b)$）、損益分岐点、期待値、記憶容量、通信時間。**実際に計算して検算してください**
- **用語の対応づけ** … OSI 参照モデルの層と機器、TCP と UDP の性質、RAID の番号と方式、ソート手法の名前と動き、経営分析指標の分子と分母
- **数字を含む定義** … 資本金・従業員数の区分、法定の日数、規格番号（ISO 9001 は品質、ISO 14001 は環境、ISO/IEC 27001 は情報セキュリティ、など）

### 2. 初心者に通じない書き方

**事実として正しくても、用語を説明なしで使っていれば失格です。** 読者は「サーバ」「プロトコル」「アルゴリズム」を一度も使ったことがない人です。

- **初出の専門用語が、その場で言い換えられていないもの**を挙げてください。「後で説明します」は方針違反です
- 抽象的な定義がたとえ話より先に来ていて、読み進められないところ
- 1 文が長く、修飾が重なって意味を取りづらいところ
- カタカナ語に「なぜその名前なのか」が添えられていないもの
- 公式がいきなり出てきて「なぜその式になるか」の説明がないところ

### 3. 節をまたいだ矛盾・重複

- 同じ用語を、節によって違う意味・違う言い換えで説明していないか
- 同じ説明が複数の節にほぼそのまま重複していないか（一方を削るべき箇所）
- 「◯◯で説明したとおり」と書いてあるのに、そこに書かれていないもの

### 4. 記法の崩れ

本文は Markdown サブセットです。`src/lib/digest.ts` が「# この節のまとめ」「> **試験のポイント**」「> **よくある勘違い**」を機械的に抜き出して直前チェックシートを作るので、**書式が崩れると拾われません。**

- 節の骨格（`# ざっくり言うと` → 本論 → `# この節のまとめ` → ` ```quiz `）が崩れていないか
- 表の列数がそろっているか
- ` ```diagram:compare ` の要素が偶数個か（1 行 1 セル、偶数行が左・奇数行が右）
- 図の中に `**強調**` を書いていないか（効きません）
- `[文字](textbook/xxx)` のリンク先が実在する節 id か。実在する id は次で全部です：
  `i-1` `i-2` `i-3` `i-4` `s-corp-1`〜`s-corp-5` `s-biz-1`〜`s-biz-5` `s-sys-1` `s-sys-2` `m-dev-1`〜`m-dev-3` `m-pm-1` `m-pm-2` `m-sm-1`〜`m-sm-3` `t-basic-1`〜`t-basic-4` `t-algo-1`〜`t-algo-3` `t-comp-1`〜`t-comp-3` `t-sys-1`〜`t-sys-3` `t-media-1`〜`t-media-3` `t-db-1`〜`t-db-3` `t-nw-1`〜`t-nw-4` `t-sec-1`〜`t-sec-5`
- ` ```quiz ` の中が `問い :: 答え` の形になっているか

## 報告の形

**最終メッセージに、指摘だけを次の形で書いてください。** 経過や感想は要りません。

```
## 重大（事実として間違っている）
1. [ファイル名 / 節id] 引用「……」
   何が問題か: ……
   どう直すか: ……
   確信度: 高 / 中 / 低

## 中（誤解を招く・初心者に通じない）
（同じ形）

## 軽微（記法・表現）
（同じ形）
```

## 最後に一つ

**「事実に自信がない箇所はありませんでした」という報告は受け付けません。** 過去に同じ形のレビューで、1 ファイルあたり平均 3 件の誤りが見つかっています。見つからなかったのなら、それは読み方が浅いということです。**確信が持てないものも「確信度: 低」として必ず挙げてください。** 拾いすぎる分には依頼側が捨てられますが、見逃したものは誰も拾えません。
