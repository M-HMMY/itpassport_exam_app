## 読者像（最重要）

**IT の知識がゼロの人**です。学生・事務職・営業職。「サーバ」「プロトコル」を一度も使ったことがない人が読みます。

- 専門用語は初出のその場で必ず言い換える。「後で説明します」は禁止
- 身近なたとえを先に置く（文化祭の準備、引っ越し、料理の段取り、店の受付、家の非常用持ち出し袋）
- 1 文を短く
- カタカナ語・アルファベットの略語には、元の英語とその意味を添える

**この章の背骨**：マネジメント系は「作る（開発技術）」「期限内に終わらせる（プロジェクトマネジメント）」「動かし続ける（サービスマネジメント）」の 3 段構えです。各章の冒頭でこの位置づけに触れてください。

## 節の骨格（厳守）

```
# ざっくり言うと          ← 日常語で「何の話か」。用語を使わずに書く
（本論。見出し・表・図・たとえ話）
> **試験のポイント** …     ← 暗記すべき事項
> **よくある勘違い** …     ← 先回りして潰す誤解
# この節のまとめ           ← 箇条書き 5〜6 個
（```quiz ブロック。1 行 1 問で「問い :: 答え」を 5〜6 個）
```

「この節のまとめ」「試験のポイント」「よくある勘違い」は `src/lib/digest.ts` が自動で抜き出して直前チェックシートに並べます。**書式を崩すと拾われません。**

## 書き方の注意

- 本文は TypeScript のテンプレートリテラル内に入ります。バックスラッシュは 2 つ重ね、バックティックはエスケープが必要です
- **bash のヒアドキュメントはバックスラッシュを落とすので使わないこと。** ファイルを直接書くか、`scripts/emit_textbook.py`（Markdown を Python の raw 文字列で書いて .ts に変換する小道具）を使ってください
- 図（三連バッククォート + `diagram:flow` / `stack` / `compare` / `tree` / `cycle` / `seq`）を積極的に使ってください。アローダイアグラムやウォータフォールの流れは図が効きます
- `compare` は「1 行 1 セル、偶数行が左・奇数行が右」で書きます。**要素が奇数個だと検査でエラーになります**
- 図の中では `**強調**` が効きません。書かないでください
- 節からのリンクは `[文字](textbook/m-pm-2)` の形。**存在するのは上の表の 8 つの id だけ**なので、それ以外へはリンクしないこと。ページへのリンクは `[直前チェックシート](sheet)` `[確認問題](practice)` が使えます

## 事実の扱い

**確信のない事実は書かないでください。** 特に注意する箇所：
- インシデント管理は「まず復旧」、問題管理は「原因の根絶」。この区別を取り違えない
- 監査人に求められるのは独立性であり、監査対象の業務を自分で行ってはいけない
- クリティカルパスは「最も余裕がない経路」で、そこが遅れると全体が遅れる
