## 読者像（最重要）

**IT の知識がゼロの人**です。学生・事務職・営業職。「サーバ」「プロトコル」を一度も使ったことがない人が読みます。

- 専門用語は初出のその場で必ず言い換える。「後で説明します」は禁止
- 身近なたとえを先に置く（家の鍵、金庫、印鑑、封筒、宅配便、受付、合鍵）
- 1 文を短く
- カタカナ語・アルファベットの略語には、元の英語とその意味を添える

**この章の背骨**：すべての対策は「**見られたくない（機密性）・書き換えられたくない（完全性）・使えないと困る（可用性）**」の 3 つのどれかを守るためにある。この軸を各節で繰り返し、バラバラの用語を一本につないでください。

## 節の骨格（厳守）

```
# ざっくり言うと          ← 日常語で「何の話か」。用語を使わずに書く
（本論。見出し・表・図・たとえ話）
> **試験のポイント** …     ← 暗記すべき事項
> **よくある勘違い** …     ← 先回りして潰す誤解
# この節のまとめ           ← 箇条書き 5〜6 個
（```quiz ブロック。1 行 1 問で「問い :: 答え」を 5〜6 個）
```

「この節のまとめ」「試験のポイント」「よくある勘違い」は `src/lib/digest.ts` が自動で抜き出して直前チェックシートに並べます。**書式を崩すと拾われません。**

## 書き方の注意

- 本文は TypeScript のテンプレートリテラル内に入ります。バックスラッシュは 2 つ重ね、バックティックはエスケープが必要です
- **bash のヒアドキュメントはバックスラッシュを落とすので使わないこと。** ファイルを直接書くか、`scripts/emit_textbook.py`（Markdown を Python の raw 文字列で書いて .ts に変換する小道具）を使ってください
- 図（三連バッククォート + `diagram:flow` / `stack` / `compare` / `tree` / `cycle` / `seq`）を積極的に使ってください。**公開鍵暗号とディジタル署名は図がないと通じません**
- `compare` は「1 行 1 セル、偶数行が左・奇数行が右」で書きます。**要素が奇数個だと検査でエラーになります**
- 図の中では `**強調**` が効きません。書かないでください
- 節からのリンクは `[文字](textbook/t-sec-2)` の形。**存在するのは `i-1`〜`i-4`、`s-corp-1`〜`s-corp-5`、`m-dev-1`〜`m-dev-3`、`m-pm-1`〜`m-pm-2`、`m-sm-1`〜`m-sm-3`、`t-basic-1`〜`t-basic-4`、`t-algo-1`〜`t-algo-3`、そして今回書く `t-sec-1`〜`t-sec-5` だけ**です。それ以外へはリンクしないこと

## 事実の扱い

**確信のない事実は書かないでください。** 特に間違えやすい箇所：

- 公開鍵暗号で**暗号化に使うのは受信者の公開鍵**、復号は受信者の秘密鍵
- ディジタル署名で**署名に使うのは送信者の秘密鍵**、検証は送信者の公開鍵
- ハッシュ関数は一方向で、元に戻せない（暗号化とは別物）
- ウイルス・ワーム・トロイの木馬の違い（自己複製するか、単独で動くか、正体を偽るか）
- ファイアウォールは通信の出入りを制御するもので、ウイルスを検出するものではない

**この 2 種類の鍵の使い分けは最頻出かつ最も間違えやすい**ので、図と本文の両方で丁寧に扱ってください。
