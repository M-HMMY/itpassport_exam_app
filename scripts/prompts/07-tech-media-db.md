## 読者像（最重要）

**IT の知識がゼロの人**です。学生・事務職・営業職。

- 専門用語は初出のその場で必ず言い換える。「後で説明します」は禁止
- **データベースの章は Excel の表を思い浮かべながら読めるように書いてください。** 「1 行が 1 件のデータ」「主キーは他と重ならない見分け札（社員番号、学籍番号）」
- **情報デザインの章は、読者が日常で不便に感じた経験がそのまま材料になります。** 押すか引くか分からないドア、分かりにくい券売機、といった身近な例から入る
- 画像のデータ量の計算は「なぜ掛け算になるか」から入る。公式の暗記を求めない
- 1 文を短く
- カタカナ語・アルファベットの略語には、元の英語とその意味を添える

## 節の骨格（厳守）

```
# ざっくり言うと          ← 日常語で「何の話か」。用語を使わずに書く
（本論。見出し・表・図・たとえ話）
> **試験のポイント** …     ← 暗記すべき事項
> **よくある勘違い** …     ← 先回りして潰す誤解
# この節のまとめ           ← 箇条書き 5〜6 個
（```quiz ブロック。1 行 1 問で「問い :: 答え」を 5〜6 個）
```

「この節のまとめ」「試験のポイント」「よくある勘違い」は `src/lib/digest.ts` が自動で抜き出して直前チェックシートに並べます。**書式を崩すと拾われません。**

## 書き方の注意

- 本文は TypeScript のテンプレートリテラル内に入ります。バックスラッシュは 2 つ重ね、バックティックはエスケープが必要です
- **bash のヒアドキュメントはバックスラッシュを落とすので使わないこと。** ファイルを直接書くか、`scripts/emit_textbook.py` を使ってください
- 図（三連バッククォート + `diagram:flow` / `stack` / `compare` / `tree` / `cycle` / `matrix` / `seq`）を積極的に使ってください。**正規化の前後、標本化と量子化の流れ、トランザクションの流れは図が効きます**
- 表を使えるので、**関係データベースの表の例は Markdown の表でそのまま見せてください**（社員表・部署表など）
- `compare` は「1 行 1 セル、偶数行が左・奇数行が右」で書きます。**要素が奇数個だと検査でエラーになります**
- 図の中では `**強調**` が効きません。書かないでください
- 節からのリンクは `[文字](textbook/t-db-1)` の形。**存在するのは `i-1`〜`i-4`、`s-corp-1`〜`s-corp-5`、`m-dev-1`〜`m-dev-3`、`m-pm-1`〜`m-pm-2`、`m-sm-1`〜`m-sm-3`、`t-basic-1`〜`t-basic-4`、`t-algo-1`〜`t-algo-3`、`t-comp-1`〜`t-comp-3`、`t-sys-1`〜`t-sys-3`、`t-nw-1`〜`t-nw-4`、`t-sec-1`〜`t-sec-5`、そして今回書く `t-media-1`〜`t-media-3`・`t-db-1`〜`t-db-3` だけ**です。それ以外へはリンクしないこと

## 事実の扱い

**確信のない事実は書かないでください。** 特に間違えやすい箇所：

- 主キーは重複せず空にもできない。外部キーは他の表の主キーを参照する
- 可逆圧縮は完全に元に戻せる（PNG・ZIP）、非可逆圧縮は戻せない代わりに小さくなる（JPEG・MP3）
- 標本化は時間方向に区切ること、量子化は値を段階に丸めること。**この 2 つの順序と役割の取り違えは頻出**
- ユニバーサルデザインは「はじめから誰にとっても使いやすく作る」、バリアフリーは「既にある障壁を取り除く」
- コミットは確定、ロールバックは取り消し。トランザクションは「全部やるか、全部やらないか」
- 排他制御をしないと起きる問題（同時更新で片方の変更が消える）を具体例で示すこと
