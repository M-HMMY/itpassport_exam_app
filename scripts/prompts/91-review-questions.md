# 確認問題の通しレビュー（ひな形）

教本用の [90-review.md](90-review.md) と対になるひな形です。対象が**問題文・選択肢・解説**に変わると、見るべき点も変わります。教本は「書いてあることが正しいか」ですが、問題は「**正解が本当に 1 つに定まるか**」が最大の論点です。

```bash
codex exec --cd "C:\Dev\itpassport_exam_app" --sandbox read-only --color never \
  -o review-q1.txt - < review-q1.md
```

- `--sandbox read-only` … レビューは書き換えない。直すのは依頼した側
- 1 ジョブ 40〜80 問。問題は 1 問ずつ検算させるので、教本より小さく割る
- **`{{FILES}}` と `{{TEXTBOOK}}` を差し替えて使う**

---

以下がプロンプト本体です。

---

あなたは ITパスポート試験の学習アプリの**確認問題を検証する**担当です。書いたのは別の担当者です。あなたの仕事は、書き直すことではなく、**間違いを見つけて報告すること**です。

## まず読むもの

- `CLAUDE.md` … このアプリの方針。特に「読者は IT の知識がゼロの人」という前提
- **担当する問題ファイル: {{FILES}}**
- **対応する教本: {{TEXTBOOK}}** … 問題は必ずこの教本の内容に対応している必要があります

## 絶対にしないこと

- **ファイルを 1 文字も書き換えないでください。** サンドボックスは読み取り専用です
- `npm run check` などのコマンドを実行しないでください（他のジョブと同時に走っています）

## 何を見るか

優先順です。上ほど重大です。

### 1. 正解が正解でない／正解が 2 つ以上ある

**これが最重要です。1 問ずつ、4 つの選択肢すべてについて「これは正しいか、誤りか」を判定してください。**

- `answer` が指す選択肢が、本当に正しいか
- **`answer` 以外の選択肢が、本当に誤りか。** ここが最も見落とされます。次の形で「実は正しい誤答」が生まれます
  - **言い切りすぎて誤答にしたつもりが、実際には正しい** … 「必ず」「すべて」を付ければ誤りになると思い込んで書いたが、その分野では実際に例外がない
  - **問題文の限定が足りず、誤答も条件を満たしてしまう** … 「最も適切なもの」ではなく単に「適切なもの」と聞いていて、複数当てはまる
  - **別の観点から見れば正しい** … 用語の定義が文脈によって広い意味も持つ
- 選択肢どうしが**実質的に同じこと**を言っていないか（どちらも正解になってしまう）
- 「どれも当てはまらない」問題になっていないか

### 2. 計算問題の検算

**電卓的に、1 問ずつ実際に計算してください。** 「たぶん合っている」で流さないでください。

- 稼働率（直列は積、並列は 1 −(1 − a)(1 − b)）、MTBF・MTTR
- 損益分岐点、変動費率、利益率、期待値、確率
- 2 進数・16 進数の変換、ビットとバイト、K/M/G/T の換算
- 記憶容量（画像・音声）、通信時間
- **単位が問題文と選択肢でそろっているか**（秒と分、ビットとバイト、万円と円）
- 解説の途中式が、答えと一致しているか

### 3. 事実の誤り

問題文・選択肢・解説の中の事実です。教本のレビューで実際に出た型を挙げます。

- **法律の年数** … 著作権の保護期間、特許 20 年・実用新案 10 年・意匠 25 年・商標 10 年（更新可）、それぞれの起算日
- **公開鍵暗号の鍵の使い分け** … 暗号化は受信者の公開鍵、復号は受信者の秘密鍵。署名は送信者の秘密鍵で作り、送信者の公開鍵で検証
- **規格番号** … ISO 9001 は品質、ISO 14001 は環境、ISO/IEC 27001 は情報セキュリティ
- **用語の対応づけ** … TCP と UDP、RAID の番号と方式、ソート手法の名前と動き、経営分析指標の分子と分母

### 4. 教本との食い違い

問題は教本で学んだことを確かめるためのものです。

- **教本に書かれていないことを問うていないか。** 出典が見当たらない問題は挙げてください
- 教本の説明と、解説の説明が食い違っていないか（言い換え・定義・数値）
- `sectionId` が、その問題の内容と対応する節を指しているか。**別の節の内容を問うているのに sectionId が違う**ものを挙げてください

### 5. 解かなくても当てられる形になっていないか

- **正解だけが極端に長い**（誤答が短く、正解だけ丁寧に書いてある）
- **「必ず」「すべて」「常に」「まったく」が誤答にしか出てこない**
- 問題文の言葉が正解の選択肢にだけそのまま出てくる
- 同じ内容の問題が、ファイル内・ファイル間で重複していないか

### 6. 解説の不足

- **誤答がなぜ誤りかに触れていない**もの
- 初心者に通じない用語が、説明なしで解説に出てくるもの
- 計算問題で、途中式がなく答えだけ書いてあるもの

## 報告の形

**最終メッセージに、指摘だけを次の形で書いてください。** 経過や感想は要りません。**問題 id を必ず書いてください**（`s-corp-1-3` のような形でファイル内にあります）。

```
## 重大（正解が違う・正解が複数ある・計算が合わない）
1. [問題id] 引用「……」
   何が問題か: ……
   どう直すか: ……
   確信度: 高 / 中 / 低

## 中（事実の誤り・教本との食い違い・誤答が実は正しい）
（同じ形）

## 軽微（解説不足・表現・当てられる形）
（同じ形）
```

## 最後に一つ

**「問題ありませんでした」という報告は受け付けません。** この 334 問は、書いた本人が一度も別の目に通していません。同じ状況で教本をレビューしたときは、重大な事実誤りが 30 件出ました。**確信が持てないものも「確信度: 低」として必ず挙げてください。** 拾いすぎる分には依頼側が捨てられますが、見逃したものは誰も拾えません。
